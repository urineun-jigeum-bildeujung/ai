# 재구매 시연용 모델 결정과 공개 경계

## 결정

- **시연 실행 모델: 사전 고정 XGBoost AFT** (`ec25eb1bcd8f24ce36a2397c1544cb087cb970af532365de7f8ec900aeb4b7fb`). 이는 이미 검증한 배치·모델 로딩·DB 적재 경로를 재사용하기 위한 **기능 시연 선택**이며, 정확도가 가장 높거나 실사용자에게 적합하다는 결론이 아니다.
- **출력: 앞으로 30일 안의 조건부 재구매 확률 한 가지.** 기간별 확률·예상 재구매일은 이번 시연 범위에 포함하지 않는다.
- **시연 실행: 2026-10-06·07 오전 09:30 KST에 각각 일회성 Job 1건씩.** 시연 기간에만 실행하고 CronJob은 활성화하지 않는다. 기존 `shadow-run`의 고정 기준 시각·생성 시각·실행 ID를 그대로 재사용하면 다음 날 새 예측이 만들어지지 않으므로, 날짜별 고정 컷과 멱등 ID를 생성하는 명령을 사용한다. 이미지 빌드·ECR 업로드·Job 실행은 인프라 담당이다.
- **운영 확률 공개: NO-GO.** 현재 평가 원천은 목데이터이고 실사용자 결과가 없다. 시연용 결과는 운영 결과와 분리하고, 사용자 대상 `PUBLISHED` 발행은 하지 않는다. 일회성 Job 검증을 운영용 정기 실행 승인으로 해석하지 않는다.
- 기존 `SHADOW` 결과는 `repurchase.latest_predictions`에 나타나지 않는다. 이 비노출 경계를 유지한다. 화면 시연이 필요하면 목계정 전용 조회 경로와 명시적인 **"목데이터 기반 시연"** 표시를 별도로 구현·검증한다. 기존 서비스 조회 뷰를 SHADOW까지 확장하지 않는다.

## 선택 근거와 한계

고정 서비스 Test 34,895행에서 AFT의 30일 IPCW Brier는 **0.166328**, LightGBM은 **0.160562**였다. 반면 AFT의 C-index는 **0.749188**, LightGBM은 **0.746836**이었다. AFT와 LightGBM의 평균 예측 확률은 각각 **17.09%**, **19.00%**로, IPCW 가중 관측률 **27.72%**보다 낮았다. Test 결과만 보고 LightGBM으로 바꾸면 사후 모델 선택이므로, 두 모델 중 어느 것도 운영 모델로 확정하지 않는다. 시연용 AFT 채택은 품질 우위 주장이 아니다.

dev에서 AFT SHADOW 배치 1회에 **50,517건**이 저장됐고, 같은 실행 ID 재시도에서 추가 저장이 없음을 확인했다. 이 검증은 추론·적재·멱등성 확인이며 사용자 품질 검증이 아니다.

## 시연 연동 완료 조건

1. 두 일회성 Job은 `--scheduled-time-kst 09:30`을 사용한다. AI의 일별 슬롯 코드는 같은 날짜 재시도에 같은 컷·ID, 다음 날짜 실행에 다른 컷·ID를 생성한다. 해당 시각의 인프라 가동 가능 여부는 인프라와 확인한다.
2. 저장은 계속 `SHADOW`만 사용한다. AI의 `demo_shadow_reader`는 인증 계층에서 받은 사용자 ID와 서버 측 목계정 허용 목록을 요구하고, 최신 시연 배치 한 건에서 그 사용자만 읽는다. 응답에는 `MOCK_DATA_DEMO` 출처·모델 버전·기준 시각을 포함한다. 이는 HTTP API나 인증 구현이 아니며, BE/FE 조회 경로와 읽기 전용 DB 권한 연결은 별도 확인한다. 기존 `latest_predictions` 뷰의 공개 조건은 변경하지 않는다.
3. 화면에는 "목데이터 기반 시연 결과이며 실제 구매를 보장하지 않음"을 30일 확률 가까이에 표시한다. 날짜·신뢰도처럼 현재 검증되지 않은 표현은 추가하지 않는다.
4. 새 이미지에서 명령 실행·같은 날짜 재실행의 멱등성·다음 날짜 새 배치·실패 시 미발행을 확인한다. 기존 50,517건 규모라 두 실행에서 약 10만 건의 결과 행이 더 쌓일 수 있다. 시연 종료 후 Job을 반복 실행하지 않고, 저장된 결과 삭제는 보관 정책을 별도로 정한 뒤 진행한다.
5. 운영 전환은 새로운 실제 사용자 관측 결과, 별도 시간순 검증, 저이력 구간·보정 평가 및 노출 정책 합의 이후 별도 결정한다.

## 두 번의 Job 실행 인계

| 실행 | 예정 시각 | AI 명령 인자 |
| --- | --- | --- |
| 1차 | 2026-10-06 09:30 KST | `demo-daily-shadow-run --scheduled-time-kst 09:30 --run-date-kst 2026-10-06` |
| 2차 | 2026-10-07 09:30 KST | `demo-daily-shadow-run --scheduled-time-kst 09:30 --run-date-kst 2026-10-07` |

두 Job 모두 새 코드가 포함된 **새 ECR 이미지**, 고정 AFT 모델 디렉터리와 아티팩트 ID, 기존 세 DB DSN Secret, `--allow-shadow-write`를 사용한다. Secret 값은 로그·메시지에 쓰지 않는다. 1차와 2차는 서로 다른 `publication_id`가 되어야 하며, 같은 날짜 재시도는 `inserted=false`여야 한다. 각 실행 후 AI는 배치 `SHADOW` 상태, 결과 건수, `latest_predictions` 비노출을 대조한다. 인프라의 서버·DB 가동과 Job 생성/실행 없이는 이 단계가 완료되지 않는다. 새 이미지 발행 및 Job 실행 전까지 기존 ECR 태그가 이 명령을 지원한다고 가정하지 않는다.

시연 후 추가 Job은 실행하지 않는다. 기존 SHADOW 데이터의 삭제는 이번 인계 범위가 아니며, 보관 정책을 정하기 전까지 유지한다.
