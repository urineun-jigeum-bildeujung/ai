# 재구매 합성 보정의 저이력 구간 진단

두 번의 합성 최종 평가에서 경과 0일·저이력 구간의 Brier 점추정 악화가 반복됐다. 이미 열린 최종 평가본을 튜닝에 재사용하지 않고, **개발본의 내부 보정 구간과 외부 Validation만** 구매 간격 수별로 다시 확인했다. 아래 수치는 합성 생성 규칙 내부의 진단이며 원인 확정이나 실사용 성능을 뜻하지 않는다.

## 앞선 개발본 v2·v3: 저이력 사용자 부재

두 개발본 모두 경과 0일 보정 적합 구간과 외부 Validation에 구매 간격 0개·1~2개 표본이 **0건**이었다. 확인 가능한 결과가 있는 표본은 모두 간격 3개 이상이었다.

| 개발본 | 내부 보정 위험집단/결과 확인 | 외부 Validation 위험집단/결과 확인 | 관찰된 간격 구간 |
| --- | ---: | ---: | --- |
| v2 | 376 / 246 | 387 / 259 | 3개 이상만 |
| v3 | 383 / 252 | 425 / 281 | 3개 이상만 |

따라서 개발 단계의 전체 Brier 개선은 신규·저이력 사용자 성능을 검증하지 못했다. 별도 최종 생성본에서 나타난 저이력 악화의 **가능한 설명**이지만, 이 정보만으로 인과적 원인을 확정할 수는 없다.

## 신규 유입을 포함한 개발본 v4: 전체 개선과 저이력 악화 동시 관찰

동일한 합성 구매 주기 생성기에 사용자별 첫 주문 유입 시점을 분산하는 옵션을 추가했다. 새 개발본은 시드 **6201**, 주문 **4,086건**, 사용자 **300명**이며, 첫 주문 유입 기간은 시작 후 **450일**이다. 최종 평가용은 별도 시드 **6202**, 주문 **4,124건**으로 생성했지만 **라벨·모델 평가에 사용하지 않았다**. 기간·키·파일 지문 사전검사와 개발 결과 재현은 통과했다.

개발 외부 Validation의 전체 Brier는 원본→Isotonic 순으로 경과 0일 **0.173248→0.143448**, 7일 **0.190314→0.136357**, 14일 **0.223159→0.128130**, 30일 **0.379054→0.105971**이었다. 그러나 0일의 이력별 쌍 비교는 다르다.

| 구매 간격 수 | 위험집단 | 결과 확인 | 실제 사건률(IPCW 가중) | 평균 원본/보정 확률 | 원본/보정 Brier |
| --- | ---: | ---: | ---: | ---: | ---: |
| 0개 | 76 | 56 | 0.271889 | 0.390584 / 0.414453 | **0.212054 / 0.218290** |
| 1~2개 | 133 | 86 | 0.324245 | 0.381528 / 0.400074 | 0.147993 / 0.115136 |
| 3개 이상 | 754 | 489 | 0.480175 | 0.387303 / 0.445581 | 0.173280 / 0.139786 |

간격 0개에서는 전체 평균 개선과 달리 보정 Brier가 **+0.006236** 높았다. 점추정 차이이며 이 구간만의 Bootstrap 신뢰구간을 산출하지 않았으므로 통계적으로 악화가 확정됐다고 주장하지 않는다. 다만 전 구간 일괄 보정을 승인하기에는 개발 단계의 반증이다.

`scripts.diagnose_independent_calibration_history`는 최종 데이터의 manifest·평가 계획과 원천 파일 해시만 검증하고, 최종 행을 라벨·피처로 파싱하거나 평가하지 않는다. 개발본의 보정 적합·외부 Validation에서 동일 행과 IPCW 가중치로 구간별 Brier를 계산한다. 진단 결과의 보수적 선별 기준은 외부 Validation에 간격 0개와 1~2개가 모두 존재하고 두 구간 모두 Brier 점추정이 악화되지 않는 것이다. v4는 **실패**했다. 이 기준은 유의성 검정이나 운영 승인 규칙이 아니라 최종 평가본을 불필요하게 열지 않기 위한 개발 단계 스크린이다.

개발 결과 SHA-256은 `9491ea255494b0b0313c3fdb1ca0a84e68eb91141092572aebc9b2769d9759ff`, v4 진단 결과 SHA-256은 `81303fa3cf846ab2de5e57b8a2609ea72cf079c61ff409687306d918724ed82f`이다. `independent_synthetic_calibration_freeze_v4.json`은 전체 Brier 기준을 사전 기록하고 개발 재현까지만 확인한 기록이며 **최종 평가가 수행됐다는 뜻이 아니다**.

결론: v4 최종 평가본은 열지 않고 보존한다. 현재 Isotonic 후보의 경과 0일 저이력 적용을 승인하지 않으며 운영 확률 공개는 계속 **NO-GO**다. 다음 후보는 신규 사용자 집단을 포함한 별도 개발본에서 설계·선택한 뒤, 저이력 구간까지 사전 합의된 평가 기준을 통과할 때만 새로운 미사용 최종 평가본으로 검증한다. 이미 생성한 v4 최종 평가본을 새 후보의 반복 튜닝에 사용하지 않는다.
