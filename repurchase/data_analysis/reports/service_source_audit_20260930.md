정확한 피처 변화는 각 anchor에서 유효한 과거 사건을 다시 구성해 확인해야 한다.

## 사용자 과거 주문 수 재계산 (2026-10-01)

적용해 `user_prior_order_count`를 실제로 다시 셌다. 결제 시각이 앵커보다
엄격히 이른 고유 주문만 포함하고, 해당 앵커에 `[시작, 종료)` 구간이 유효한

한꺼번에 결합하지 않는다. 독립 검토에서 대규모 결합의 메모리 위험을 찾아
계산 방식을 변경했고, 변경 전후 추출본 결과가 같음을 확인했다.

모델 학습·평가 결과는 아직 재계산하지 않았으므로 성능 개선으로 해석하지 않는다.

재계산했다. 각 앵커에 활성이고 `paid_at <= anchor_at`인 동일 대상의 고유
구매 사건을 결제 순서로 정렬해, 직전 구매 간격 수·중앙값·MAD·상대 MAD를
기존 학습 정의와 동일하게 계산했다. 현재 주문 사건이 앵커에 없거나, 같은
대상에 서로 다른 주문이 동일 시각 결제됐다면 조용히 순서를 만들지 않고
오류로 거절한다. 취소로 전부 무효였던 시간 공백과 이후 재활성화도 구간대로
반영한다.

83,327개 표본에서 최종 스냅샷 피처 대비 **구매 간격 수 80건(0.0960%)**,
**중앙값 80건(0.0960%)**, **MAD 62건(0.0744%)**, **상대 MAD 62건(0.0744%)**이
달랐다. 부동소수점 결과는 `rtol=1e-9`, `atol=1e-9`로 비교했다. 단순 값의
완전 일치만 요구하면 중앙값 8,101건 등 작은 계산 정밀도 차이를 실제
피처 변경으로 잘못 셀 수 있다. 대상별 앵커 수×구간 수의 합은 **278,492**,
최대 단일 대상은 **484**였고, 이 추출본에서 재계산 함수 자체는 **약 39초**
걸렸다. 이는 로컬 1회 측정이며 배포 성능 보증이 아니다. 생존 라벨과
모델 재학습·평가는 아직 진행하지 않았다.
