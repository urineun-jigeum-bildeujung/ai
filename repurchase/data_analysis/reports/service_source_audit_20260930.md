정확한 피처 변화는 각 anchor에서 유효한 과거 사건을 다시 구성해 확인해야 한다.

적용해 `user_prior_order_count`를 실제로 다시 셌다. 결제 시각이 앵커보다
엄격히 이른 고유 주문만 포함하고, 해당 앵커에 `[시작, 종료)` 구간이 유효한

## 동일 Validation의 AFT·LightGBM 탐색 비교 (2026-10-01)

같은 서비스 피처 버전 `2`, 30일 시점, Validation 신규 구매 앵커 **18,905건**을

### 동일 추출본의 비교 함수 재현성 점검 (2026-10-01)

동일한 여섯 CSV의 해시, 시간 컷, 학습 설정과 평가 표본을 유지해도 AFT
지표가 달라지는 문제를 확인했다. ID를 숫자형으로 읽으면 AFT 20회 Brier가
**0.125327**, 문자열형으로 읽으면 앞선 기록과 같은 **0.124972**였다.

IPCW 비교 가능 쌍 **38,010,214개**는 같았고, LightGBM Brier는 두 경우

### 동일 평가행의 Brier 차이 기여도 (2026-10-02)

### AFT 반복 횟수의 Train 내부 선택 (2026-10-02)

바깥 Validation에서 AFT 20회를 고르는 순환을 줄이기 위해, 각 바깥 Train의
시간 길이 앞 80%를 **내부 Train**, 뒤 20%를 **내부 Validation**으로
나눴다. 내부 Train·Validation 생존 라벨은 각각의 종료 시각에서 다시
생성하고, 내부 정답 확인 행의 30일 IPCW Brier가 가장 낮은 반복 횟수를
선택한다. 동점이면 더 적은 횟수를 택한다. 선택을 끝낸 뒤에만 바깥
Validation 라벨을 생성하며, 선택된 횟수로 바깥 Train 전체를 재학습한다.
기존 고정 20회 실행 경로도 유지한다.

원천 CSV 6개와 해시, 관측 종료 가정 `2026-09-29T15:44:00+09:00`,
AFT `normal/scale 1.0`, LightGBM 설정, IPCW 평가, 사용자 단위 쌍
Bootstrap 1,000회(seed 42)는 직전 세 구간 실험과 같다. 실행 인자는 기존
명령에 `--aft-round-candidates 5 20 50 100 --inner-train-ratio 0.8`을
추가한다. 아래 내부 Brier의 분모는 **각 내부 Validation의 IPCW 정답 확인
행**이며, 바깥 Validation 점수와 직접 비교하는 값은 아니다.

AFT·LightGBM Brier, C-index, ECE 및 Bootstrap 반복값은 기존 고정
20회 실행과 **새 선택 기록 필드 외에 정확히 일치**했다. 바깥 Brier 차이
`AFT − LightGBM`은 시간 순서대로 **-0.003415, -0.003151,
+0.002711**로, 우위 방향은 여전히 역전된다. 내부 선택은 20회라는
결정이 각 바깥 Validation 점수 자체에 의존하지 않도록 만들었지만,
**후보 격자와 AFT 분포·scale은 앞선 Validation 탐색의 영향을 받았다.**
따라서 독립적인 하이퍼파라미터 선택이나 Test 성능 보증으로 해석하지
않는다. 운영 모델은 미선정이며 Test는 봉인 상태다.

세 로컬 재현 결과는
`/private/tmp/repurchase-service-aft-train-selection-{40-55,55-70,70-85}.json`에
후보 점수·선택 컷·원천 해시와 함께 저장했다. 원천 CSV와 반복값 원자료는
Git에 올리지 않는다. 다음에는 모델 설정 후보 전체를 Train 내부에서만
정의·선택하고, 별도의 시간 이동 구간에서 선택 절차 자체의 안정성을
확인해야 한다.

### AFT scale의 Train 내부 선택 (2026-10-02)

직전 반복 횟수 실험의 내부 시간 컷을 그대로 사용하고, normal 분포와
부스팅 20회는 고정한 채 **scale 0.5/1.0/2.0만** 비교했다. 각 scale은
학습 손실과 30일 확률 변환에 모두 들어가므로 후보마다 내부 Train에서
새 모델을 학습했다. 동일 내부 Validation 행·IPCW 가중치의 30일 Brier가
최소인 scale을 고르고, 동점이면 낮은 scale을 택한다. 이후 선택한 scale로
바깥 Train 전체를 재학습하고 바깥 Validation을 평가했다. 두 설정 탐색을
섞지 않기 위해 반복 횟수 후보와 scale 후보의 동시 지정은 거절한다.

원천 CSV 6개와 해시, 관측 종료 가정 `2026-09-29T15:44:00+09:00`,
피처 버전 2, LightGBM 설정, 사용자 쌍 Bootstrap 1,000회(seed 42)는
직전 실험과 같다. 기존 실행 명령에서 반복 횟수 후보 대신
`--aft-scale-candidates 0.5 1.0 2.0 --inner-train-ratio 0.8`을 사용했다.

| 바깥 Train/Validation 종료 비율 | 내부 정답 확인 | 내부 Brier scale 0.5 | 1.0 | 2.0 | 선택 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 40/55% | 1,358 | 0.115995 | 0.098363 | **0.093269** | 2.0 |
| 55/70% | 4,109 | 0.123541 | 0.110134 | **0.106014** | 2.0 |
| 70/85% | 8,448 | 0.115503 | 0.106801 | **0.103415** | 2.0 |

세 구간 모두 scale 2.0을 선택했다. 바깥 Validation에서 기존 scale 1.0의
AFT Brier는 0.112227/0.106821/0.125268, 선택 scale 2.0의 Brier는
**0.106831/0.103197/0.120627**로 각각 0.005395/0.003625/0.004642
낮았다. 같은 행의 LightGBM Brier는 0.115642/0.109972/0.122557로
변하지 않았다. 선택 AFT−LightGBM Brier 차이는
**-0.008811/-0.006776/-0.001930**이며 사용자 단위 쌍 Bootstrap의
95% 구간은 각각 -0.010893~-0.006475, -0.008284~-0.005420,
-0.002825~-0.001039였다. AFT C-index는 0.658876/0.692066/0.703452,
ECE는 0.013216/0.006910/0.027546였다. Test는 열지 않았다.

이 비교는 **scale만 분리한 탐색 실험**이다. 20회 고정값, normal 분포,
scale 후보 격자는 과거 Validation 탐색과 모델 선택 이력의 영향을 받을 수
있다. 따라서 세 바깥 구간의 개선이 독립 Test 성능이나 운영 모델 선정을
보장하지 않는다. 실제 사용자 데이터가 아닌 목데이터의 분포와 생성 가정에도
의존한다. 로컬 재현 결과와 후보별 행 수·점수·해시는
`/private/tmp/repurchase-service-aft-scale-selection-{40-55,55-70,70-85}.json`에
보관하고 원천 CSV 및 사용자별 반복값은 Git에 올리지 않는다.

### 모델 선정 기준 고정 및 최종 평가 게이트 (2026-10-02, #176)

이 시점의 결론은 **AFT가 최종 운영 모델로 선정되었다**가 아니라,
`normal`/20회/scale 2.0 AFT를 LightGBM 피처 버전 2와 비교할
**최종 평가 후보로 고정한다**는 것이다. 세 바깥 Validation 구간에서
30일 IPCW Brier의 `AFT − LightGBM`은
**-0.008811/-0.006776/-0.001930**이고, 사용자 단위 쌍 Bootstrap
95% 구간은 모두 0보다 작다. 반면 AFT ECE는
**0.013216/0.006910/0.027546**으로 시간 구간별 차이가 있어,
Brier 우위만으로 확률 보정이나 사용자에게 보여 줄 신뢰도를 보증하지 않는다.

후속 비교에서는 **같은 평가 행, 같은 30일 라벨, 같은 IPCW 가중치와
시간 컷**을 유지한다. 1차 비교 지표는 30일 IPCW Brier이며,
IPCW C-index·ECE·calibration curve·이력량별 오차와 사용자 단위 쌍
Bootstrap을 함께 기록한다. 어느 한 보조 지표가 악화되면 Brier만으로
운영 채택을 선언하지 않고, 해당 구간과 사용자 노출 정책을 별도로 검토한다.
허용 가능한 확률 보정 오차와 서비스 실패 시 정책은 아직 합의되지 않았으므로
임의의 임계값을 만들지 않는다.

위 후보와 비교 절차를 고정한 뒤에도 **Test는 현재 봉인 상태**다.
Test를 열기 전에는 관측 종료 컷, 평가 대상·제외 기준, 학습 입력 버전,
아티팩트 해시 및 지표 산출 명령을 확정해야 한다. Test는 최종 독립 확인에만
사용하고, 그 결과에 맞춰 후보나 설정을 다시 고르지 않는다. 이 단계의
수치는 목데이터와 반복 사용한 Validation에 대한 탐색 결과이며, 실제
사용자 성능·배포 성능·날짜/범위/신뢰도 제공 가능성을 뜻하지 않는다.

### 최종 평가 입력 사전검증 경로 (#179)

별도 `scripts.validate_service_final_evaluation` 명령은 사전검증용 manifest,
기존 Validation 결과 JSON, 원천 CSV 6개의 경로를 받아 **설정부터 검사**한다.
manifest에는 `schema_version=1`, 기존 결과와 동일한
`source_sha256`·`runtime_versions`·`feature_generation_version`·관측/분할 컷,
`aft_configuration`(normal/20회/scale 2.0), `evaluation`(30일 IPCW Brier,
사용자 Bootstrap 1,000회·seed 42), 현재 `modeling/*.py` 및 비교 실행
스크립트의 `code_sha256`을 명시한다. 파일 해시와 코드 지문은 설정 검증 뒤
대조한다. 원천 파일은 바이트 해시만 읽고 행·Test 라벨·성과는 파싱하지 않는다.

통과 상태 `input_contract_verified`는 **입력 계약 일부가 일치한다**는 뜻이다.
최종 Test 실행 허가, 모델 아티팩트의 재현성, LightGBM 학습 설정 전체의
고정 또는 운영 모델 승인을 뜻하지 않는다. 실제 manifest를 승인·고정하고
나머지 평가 대상/제외 기준과 아티팩트 계약을 확인하는 작업은 별도로 남는다.

### 두 모델 학습 설정 기록 (#182)

Validation 결과 JSON에 실제 학습 팩토리에서 얻은 XGBoost AFT 파라미터와
부스팅 횟수, LightGBM의 기본값 포함 파라미터 **22개**를
`model_configuration`으로 기록한다. 사전검증은 이를 manifest, Validation
결과, 현재 코드의 학습 팩토리 사이에서 대조하며 누락·변경은 원천 파일을
읽기 전에 거절한다. 기존 결과 JSON에는 이 필드가 없으므로 새 계약에
사용하려면 Validation을 다시 실행해야 한다.

같은 로컬 원천 추출본의 70/85% 컷을 Validation만 재실행해 AFT
`normal`/20회/scale **2.0**, LightGBM 설정 22개가 결과에 기록되는 것을
확인했다. 결과의 30일 IPCW Brier는 AFT **0.120627**, LightGBM
**0.122557**이며, 사용자 단위 쌍 Bootstrap 1,000회(seed 42)의
`AFT − LightGBM` 95% 구간은 **-0.002825~-0.001039**다. 앞선 동일 컷
실험의 수치와 반올림 수준에서 일치하고 `test_evaluated=false`다.
로컬 결과는 `/private/tmp/repurchase-service-model-config-validation-70-85.json`에
보관했다. 목데이터 Validation 탐색 결과이지 Test·실사용자 성능이 아니다.
모델 아티팩트 파일 해시, 평가 대상/제외 기준 및 최종 manifest 승인은 아직
남아 있으므로 이 변경만으로 Test를 열지 않는다.

### 최종 평가 모집단 정책 기록 (#186)

기존 시간 분할과 30일 IPCW·모델별 학습 규칙을
`evaluation_population_policy`로 결과 JSON에 명시한다. Train 앵커는
`anchor_at <= train_end_at`, Validation 앵커는
`train_end_at < anchor_at <= validation_end_at`이며, 후속 Test 정책은
`validation_end_at < anchor_at <= observation_end_at_assumption`으로
기록한다. **이 단계에서 Test 앵커를 생성하거나 정답을 읽지는 않는다.**

30일 이내 관측 재구매는 사건, 30일 이상 관측되고 그 전 사건이 없으면
미발생 정답으로 취급한다. 30일 전에 검열된 행은 평가 모집단에는 남기되
IPCW 가중치를 0으로 둔다. 두 후보는 같은 평가행을 사용한다. AFT의 0일
기간 제외는 AFT **학습에만** 적용하고, LightGBM 학습은 30일 정답을
확인할 수 있는 Train 행만 사용한다. manifest·Validation 결과·현재 정책이
다르면 사전검증에서 원천 파일 접근 전에 거절한다.

같은 로컬 목데이터의 70/85% Validation을 재실행한 결과, 이전 JSON과
새 모집단 정책 필드를 제외한 값이 **정확히 일치**했다. 정답 확인
**13,381행**, AFT Brier **0.120627**, LightGBM Brier **0.122557**,
사용자 쌍 Bootstrap 95% 구간(AFT−LightGBM)
**-0.002825~-0.001039**이다. Test는 평가하지 않았고 결과는
`/private/tmp/repurchase-service-population-validation-70-85.json`에 보관했다.
이 정책 기록은 향후 Test 구현의 입력 계약일 뿐, Test 실행 허가나
아티팩트·최종 manifest 승인으로 해석하지 않는다.
