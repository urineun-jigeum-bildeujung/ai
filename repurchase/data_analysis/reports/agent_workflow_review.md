| 반복 계산의 비용을 실제로 측정할 필요 | `model_selection.py`의 후보별 동일 IPCW 처리 반복 | B/C 각 1회 학습·예측 재사용을 다음 설계에 반영. 공통 가중치 전처리 분리는 별도 검토하고, 측정 전 비용 절감률은 주장하지 않음 |
| 지적과 채택 여부가 남아야 독립 검토를 증명할 수 있음 | 기존 커밋·테스트만으로 검토자의 기여를 구분하기 어려움 | 채택. 이 기록에 근거·판단·반영 상태를 남김 |

잘된 점으로 확인된 근거:

- [피처 비교 테스트](../tests/test_model_selection.py)는 실제 학습 정답·가중치,
  예측 행, 결측 보존, 원본 불변성을 확인한다. 표본 수만 같은지 확인하는
  검사보다 비교 조건을 구체적으로 검증한다.
- [실행기](../scripts/run_uci_lightgbm_feature_comparison.py)는 설정·버전·분할·피처를
  저장하며, [보고서](uci_lightgbm_feature_comparison.md)는 단계별 차이를 인과 효과로
  해석하지 않도록 범위를 명시한다.

## 다음 B–C 비교에 적용할 항목

아래 항목은 설계에 채택했으며, 이 기록 시점에는 아직 구현하지 않았다.

1. 사용자·주문·상품 키, 행 순서, 정답, IPCW 가중치를 맞춘 B/C 예측표를 만든다.
2. 동일한 사용자 추출 목록을 두 모델에 적용하고 개선량을 `Brier(B) − Brier(C)`로 계산한다.
3. B와 C는 각각 한 번 학습하고 예측을 재사용한다. 학습 횟수·실행 시간을 측정한다.
4. 사용자 수·정답 확인 행 수·seed·반복 수·점추정·95% 구간과 해석 범위를 함께 저장한다.
5. 기본 코드 설명 → 작은 구현·검증 → 이해 확인 → 다음 확장 순서로 진행한다.

## 검토 에이전트 운영 기준

- 중간 커밋, 새로운 실험 결과, PR 준비 등 의미 있는 단위에서 실행한다.
- 출력은 근거가 있는 주요 지적 최대 3개, 다음 단계 개선안, 확인하지 못한 범위로 제한한다.
- 근거 위치·문제·제안·채택 또는 보류 이유를 기록하고, 수정 완료와 계획을 구분한다.
- 지적 개수나 에이전트 수를 성과로 삼지 않는다. 검증되지 않은 생산성 향상 수치는 적지 않는다.
- 메인 에이전트가 구현을 통합하고 검토 에이전트는 읽기 전용으로 유지한다.
- 이번 역할은 매 단계 상시 실행되거나 다른 에이전트를 자동 감독하는 백그라운드 작업이 아니다.

## 2026-09-17 · B/C 비교 입력 연결 검토

사용자 요청에 따라 검토 의견을 결과 해석, 확인되지 않은 범위, 다음 검증의
우선순위로 구성했다. 모델 성능에 관한 새 수치는 이번 단계에서 생성하지 않았다.

| 검토 의견 | 확인 수준 | 조치 |
| --- | --- | --- |
| 같은 위치의 결측 식별자가 기존 정렬 검증을 통과함 | 검토 에이전트가 합성 1행 입력으로 재현. 실제 UCI 오류는 확인하지 않음 | 공통 정렬 검사에 키 결측 거절 추가. 세 표의 키가 모두 결측인 경우도 테스트 |
| 같은 구매 키여도 30일과 60일 예측은 비교 대상이 다름 | 향후 잘못된 호출 가능성. 현재 결함으로 확정하지 않음 | 연결 함수 설명에 사건 정의·기간·기준 시점의 일치는 호출부 책임으로 명시. 다음 B/C 학습 연결 시 검증 |
| 정렬 성공은 개선의 증거가 아님 | 통계 해석 범위 | 이번 결과를 비교 입력 연결 검증으로 기록. B/C 개선 안정성은 후속 Bootstrap에서 판단 |

메인 구현: `build_paired_probability_predictions`를 추가하고 기존 k=8/LightGBM
쌍 비교도 재사용하도록 변경했다. 원본 정답·IPCW 가중치와 미관측 행을 보존하며,
인덱스 번호가 달라도 구매 키 순서가 같으면 확률을 연결한다. 키 누락·중복·결측,
순서 불일치, 중복 열 이름은 거절한다.

검증: 관련 모델 선택·E2E·평가 테스트 56개 통과. 서로 다른 인덱스, 두 모델 각각의
순서 변경·표본 누락·중복 키, 확률 열 누락, 동일 위치 결측 키, 원본 불변성을 확인했다.
기존 작은 E2E와 k=8/LightGBM Bootstrap 연결 테스트도 통과했다.

다음 우선순위: 같은 30일 예측 조건으로 B/C를 각각 한 번 학습한 뒤 이 연결
함수에 전달한다. 사용자 재표집과 실제 데이터 실행은 그 다음 단위로 분리한다.

검토 출력 기준: 완료 단위마다 근거 있는 판단, 아직 확인하지 못한 조건,
우선 검증할 항목을 제안한다. 진단 가설과 재현된 결함을 구분하고 구현 범위를
불필요하게 늘리지 않는다.
