잘된 점으로 확인된 근거:

- [피처 비교 테스트](../tests/test_model_selection.py)는 실제 학습 정답·가중치,
  예측 행, 결측 보존, 원본 불변성을 확인한다. 표본 수만 같은지 확인하는
  검사보다 비교 조건을 구체적으로 검증한다.
- [실행기](../scripts/run_uci_lightgbm_feature_comparison.py)는 설정·버전·분할·피처를
  저장하며, [보고서](uci_lightgbm_feature_comparison.md)는 단계별 차이를 인과 효과로
  해석하지 않도록 범위를 명시한다.

## 다음 B–C 비교에 적용할 항목

아래 항목은 설계에 채택했으며, 이 기록 시점에는 아직 구현하지 않았다.

1. 사용자·주문·상품 키, 행 순서, 정답, IPCW 가중치를 맞춘 B/C 예측표를 만든다.
2. 동일한 사용자 추출 목록을 두 모델에 적용하고 개선량을 `Brier(B) − Brier(C)`로 계산한다.
3. B와 C는 각각 한 번 학습하고 예측을 재사용한다. 학습 횟수·실행 시간을 측정한다.
4. 사용자 수·정답 확인 행 수·seed·반복 수·점추정·95% 구간과 해석 범위를 함께 저장한다.
5. 기본 코드 설명 → 작은 구현·검증 → 이해 확인 → 다음 확장 순서로 진행한다.

## 검토 에이전트 운영 기준

- 중간 커밋, 새로운 실험 결과, PR 준비 등 의미 있는 단위에서 실행한다.
- 출력은 근거가 있는 주요 지적 최대 3개, 다음 단계 개선안, 확인하지 못한 범위로 제한한다.
- 근거 위치·문제·제안·채택 또는 보류 이유를 기록하고, 수정 완료와 계획을 구분한다.
- 지적 개수나 에이전트 수를 성과로 삼지 않는다. 검증되지 않은 생산성 향상 수치는 적지 않는다.
- 메인 에이전트가 구현을 통합하고 검토 에이전트는 읽기 전용으로 유지한다.
- 이번 역할은 매 단계 상시 실행되거나 다른 에이전트를 자동 감독하는 백그라운드 작업이 아니다.
