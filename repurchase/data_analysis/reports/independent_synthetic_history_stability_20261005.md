# 재구매 보정의 저이력 표본 확대 실험

앞선 합성 개발본 v4의 저이력 표본이 작아, 같은 생성 규칙에서 사용자 수와 관측 기간을 늘린 **새 개발본 v5**로 안정성을 확인했다. 이는 합성 파이프라인 진단이며 실사용자 성능이나 운영 모델 선정 근거가 아니다.

## 실험 범위

- 개발본: 시드 7201, 사용자 **1,200명**, 주문 **21,168건**, 기간 2035-08-24~2037-08-13 UTC, 첫 주문 유입 기간 600일.
- 별도 최종 평가본: 시드 7202, 주문 21,854건을 생성했으나 **행·라벨·피처를 읽거나 평가하지 않았다**. 개발 진단기는 최종 평가본 경로를 입력으로 받지 않는다.
- 기존 AFT 20 rounds / scale 1.0, 내부 보정 Isotonic, 경과 0·7·14·30일의 30일 재구매 확률. 변경한 것은 합성 개발본 규모와 기간뿐이다. 실제 데이터 생성 규칙 자체는 v4와 동일하다.
- 개발 결과 SHA-256: `aa184ca12328c0008dc37f554bb9e110b724fce08f8cca2b8a663d80d509d182`. 원천 manifest SHA-256: `3e0e58fa769296c9bc95e356b21c6e47b6e02dd7ec71cca52fb42b5e9cef086a`.

## 외부 Validation의 구매 간격 0개 구간

동일 행·IPCW 가중치로 원본과 보정을 비교했다. 개선량은 **원본 Brier − 보정 Brier**이며, 신뢰구간은 해당 구간의 사용자를 1,000회 복원추출한 것이다.

| 경과일 | 위험집단 / 결과 확인 | 원본 Brier | 보정 Brier | 개선량 95% 구간 |
| ---: | ---: | ---: | ---: | ---: |
| 0 | 334 / 268 | 0.222773 | 0.218843 | −0.009851 ~ +0.016774 |
| 7 | 328 / 252 | 0.250597 | 0.251069 | **−0.008279 ~ +0.006892** |
| 14 | 312 / 241 | 0.260824 | 0.234375 | −0.000749 ~ +0.053704 |
| 30 | 178 / 135 | 0.287865 | 0.152943 | +0.060745 ~ +0.202972 |

7일의 점추정 악화량은 **0.000473**으로 작고 신뢰구간은 0을 포함한다. 통계적으로 악화가 확정됐다는 뜻은 아니다. 반대로 0·7·14일의 신뢰구간만으로 저이력 개선이 안정적이라고 주장할 수도 없다. 구매 간격 1~2개와 3개 이상은 네 경과일 모두 점추정 개선됐지만, 이 결과로 0개 구간의 불확실성을 덮지 않는다.

같은 v5 개발본에서 단일 Platt 보정과 구매 간격 수를 입력한 로지스틱 보정도 탐색했으나, 7·14일의 간격 0개 구간 점추정 악화를 제거하지 못했다. 이 두 후보는 동결하거나 최종 평가하지 않았다.

## 판정과 재현 경계

전체 평균 개선만으로 일괄 Isotonic 보정을 승인하지 않는다. 표본 확대 후에도 7일 저이력 구간의 비악화 선별 기준은 통과하지 못했다. 특히 합성 생성 규칙과 실제 서비스 데이터의 차이가 남아 있어, **운영 확률 공개 NO-GO**를 유지한다. 기존 봉인 Test 또는 새 최종 평가본을 후보 재선택에 사용하지 않는다.

원천은 Git에 포함하지 않는다. `scripts.generate_independent_synthetic_sources`의 `--user-count 1200 --duration-days 720 --arrival-span-days 600 --first-seed 7201 --start-at 2035-08-24T00:00:00+00:00`으로 생성하고, `scripts.run_service_probability_calibration`의 기존 설정으로 개발 결과를 만든 뒤 `scripts.diagnose_independent_development_history`를 실행한다. 진단기는 개발 결과의 원천·코드 지문과 각 경과일의 전체 Brier 재현을 확인한 후 이력별 사용자 Bootstrap을 계산한다.
