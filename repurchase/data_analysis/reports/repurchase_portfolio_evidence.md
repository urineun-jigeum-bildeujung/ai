# 재구매 예측 실험 수치와 의사결정 기록

## 2026-09-17 · LightGBM 30일 내 재구매 확률

UCI Online Retail II에서 같은 사용자의 동일 상품 재구매를 예측했다.
반려동물 서비스 실사용 데이터에 대한 성과가 아니라 공개 이커머스 데이터의
시간 분리 Validation 결과다. 다음 구매일까지의 오차(MAE)와 30일 내 구매
확률 오차(Brier)는 서로 다른 평가이므로 함께 혼용하지 않는다.

| 항목 | 기록 |
| --- | --- |
| 학습 입력 | 정답이 확인된 Train 473,572행, IPCW 가중치 사용 |
| 평가 전체 | Validation 97,340행 |
| 30일 결과 확인 | 73,542행. 나머지를 미재구매 정답으로 바꾸지 않음 |
| 비교 기준 | 계층형 재구매 확률 모델, 상품 수축 강도 k=8 |
| 후보 | 과거 구매 이력 피처 4개의 LightGBM 이진분류 |
| 기준 / 후보 Brier | 0.0978098525 / 0.0822656220 |
| Brier 절대 감소 | 0.0155442306 |
| Brier 상대 감소 | **15.8923%** = (기준 − 후보) / 기준 × 100 |
| 평균 Calibration 오차(ECE) | 0.0104036444 → 0.0371831821로 악화 |
| Bootstrap | 정답 확인 표본에 포함된 사용자 1,926명을 단위로 1,000회 복원추출, seed=42 |
| 개선량 95% percentile 구간 | +0.0056639900 ~ +0.0301293953 |
| 개선된 Bootstrap 반복 | 1,000/1,000회. 정확도 100% 또는 향후 개선 확률 100%가 아님 |

Bootstrap은 학습된 두 모델의 예측을 고정하고 사용자 구성을 재표집했다.
매 반복마다 모델을 재학습하거나 검열 가중치를 재추정한 결과가 아니므로
학습 데이터 변동·검열모형 추정·모델 선택·미래 분포 변화에 따른 전체
불확실성을 포함하지 않는다. 이 구간은 C와 k=8의
비교에만 적용하며 B와 C의 차이에 재사용하지 않는다.

## 피처 단계별 추가 비교

| 후보 | 입력 | IPCW Brier | ECE | 직전 후보 대비 Brier 상대 감소 |
| --- | --- | ---: | ---: | ---: |
| A | 과거 구매 간격 수 + 사용자 과거 주문 수 | 0.0929649191 | 0.0654204353 | 해당 없음 |
| B | A + 과거 구매 간격 중앙값 | 0.0828554197 | 0.0371501148 | 10.8745% |
| C | B + 구매 간격 상대 MAD | 0.0822656220 | 0.0371831821 | 0.7118% |

- 동일한 학습·평가 행, 정답, 가중치, 모델 설정을 사용했다. 결측 피처 때문에
  후보별로 표본을 추가 삭제하지 않았다.
- Brier 개선량은 A→B +0.0101094994, B→C +0.0005897978이다.
- 단계적 추가 순서에 조건부인 비교이며 개별 피처의 독립적 인과 효과는 아니다.
- C의 Brier·ECE·MCE와 시간 분할이 기존 네 피처 실행 결과와 일치했다.
- B와 C 사이의 개선 안정성은 아직 검증하지 않았다. 다음에 사용자 단위
  쌍 비교 Bootstrap으로 확인한다.

실행: `python -m scripts.run_uci_lightgbm_feature_comparison`.

## 구현 검증과 협업 기록

- `35a1475` 기준 재구매 분석 테스트 전체 284개 통과, Ruff 검사 통과.
  기존 테스트를 포함한 총수이며 이번에 284개를 새로 작성했다는 뜻은 아니다.
- 피처 선택 시 정답 열 유입·중복 열·빈 목록을 거절하고, 모델에 저장된 학습
  열 이름으로 예측 입력 순서를 맞췄다.
- 실제 학습 함수에 전달된 행·정답·가중치를 테스트에서 대조해 후보별
  표본 보존을 확인했다. Test 표본을 피처 비교에 전달하면 거절한다.
- 사용자는 사용자 단위 평가와 결측 표본 보존의 이유를 질문·검토하며
  단계적 피처 실험 진행에 동의했다. 코드 작성·실행·수치 추출은 메인
  에이전트가 수행했다. 사용자가 모든 코드를 직접 작성했다고 기술하지 않는다.
- 2026-09-17 읽기 전용 `workflow_reviewer`를 추가해 작업 방식·검증 근거·학습
  진행을 독립 점검하도록 했다. 검토 결과와 채택 여부는
  [작업 방식 검토 기록](agent_workflow_review.md)에 남긴다.
- 에이전트 활용 시간 절감률·버그 발견률은 아직 측정하지 않았다. 이력서에
  임의의 생산성 수치를 쓰지 않는다.
